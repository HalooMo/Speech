================================================================================
  SpeechLab API — руководство для клиентских приложений
================================================================================

Документ описывает HTTP API дубляжа так, чтобы по нему можно было реализовать
клиент (веб, мобильный, скрипт). Серверные секреты (Fish, Sync Labs, HF, LLM)
клиенту не передаются и здесь не перечисляются.

Базовый URL (пример продакшена):
  https://app.vandum.ru

Что делает сервис:
  Принимает видео/аудио → переводит диалог → озвучивает (Fish TTS clone) →
  собирает MP4 дубляжа.
  Режимы:
    voiceover — закадровый: дубляж + оригинальная дорожка (~30%)
    full      — полная замена аудио + Sync Labs lipsync по репликам (speech_*)

Результат: файл {project_name}_dubbed.mp4


--------------------------------------------------------------------------------
1. Эндпоинты (сводка)
--------------------------------------------------------------------------------

  Метод   Путь                              API-ключ   Назначение
  ------  --------------------------------  ---------  -------------------------
  GET     /health                           нет        живость сервиса
  GET     /api/v1/cast-voices               да         список встроенных голосов
  POST    /api/v1/dub                       да         создать задачу дубляжа
  GET     /api/v1/jobs                      да         список последних задач
  GET     /api/v1/jobs/<id>                 да         статус одной задачи
  GET     /api/v1/jobs/<id>/download        да         скачать MP4 (status=done)

Очередь: одновременно выполняется только ОДНА задача. Если занято — POST /dub
вернёт HTTP 503.


--------------------------------------------------------------------------------
2. Аутентификация
--------------------------------------------------------------------------------

Ключ выдаёт администратор сервера (клиентский SPEECHLAB_API_KEY).

Передавать в каждом запросе к /api/* одним из способов:

  X-API-Key: ВАШ_КЛЮЧ
  Authorization: Bearer ВАШ_КЛЮЧ

Без ключа / неверный ключ:
  HTTP 401
  {"error":"Неверный или отсутствующий API key (X-API-Key)"}


--------------------------------------------------------------------------------
3. GET /health
--------------------------------------------------------------------------------

Без API-ключа. Для мониторинга / перед длинной загрузкой.

  curl https://app.vandum.ru/health

Ответ 200:
  {
    "status": "ok",
    "service": "speechlab",
    "env": "production",
    "active_job": "b5d778b84a21"   // или null, если свободен
  }

active_job — id текущей queued/running задачи.


--------------------------------------------------------------------------------
4. Жизненный цикл задачи
--------------------------------------------------------------------------------

Типичный клиентский поток:

  1. (опционально) GET /api/v1/cast-voices — выбрать cast_voice
  2. POST /api/v1/dub — получить job { "id", "status":"queued", ... } → HTTP 202
  3. Poll GET /api/v1/jobs/<id> каждые 30–60 с
       queued → running → done | error
  4. При done: GET /api/v1/jobs/<id>/download → сохранить MP4

Поля объекта job (JSON):

  id                string   идентификатор задачи
  status            string   queued | running | done | error
  project_name      string
  source_language   string
  target_language   string
  video_path        string   путь на сервере (информационно)
  created_at        string   ISO-8601 UTC
  started_at        string|null
  finished_at       string|null
  result_path       string|null   путь к MP4 на сервере (при done)
  error             string|null   текст ошибки (при error)
  options           object   опции, переданные при создании
  pid               number|null   PID воркера (служебно)

Время выполнения: обычно от ~10 минут до часа+ (длина ролика, GPU, full+lipsync).


--------------------------------------------------------------------------------
5. POST /api/v1/dub — создать задачу
--------------------------------------------------------------------------------

Content-Type:
  A) multipart/form-data  — загрузка файла (основной способ)
  B) application/json     — video_path уже на сервере

Успех: HTTP 202 + тело job (см. §4).


--- 5.1. Обязательные поля ---

  project_name       буквы/цифры/_/- , длина 1–64
  source_language    язык оригинала: en, ru, de, es, fr, auto, …
  target_language    язык дубляжа
  video              файл (multipart)  ИЛИ
  video_path         абсолютный путь на сервере (JSON, только upload/projects)

Алиасы: source_lang / target_lang.

Форматы video: .mp4 .mkv .mov .avi .webm .wav .mp3 .m4a
Лимит upload по умолчанию: 500 МБ → при превышении HTTP 413.


--- 5.2. Голос (обязателен) ---

Нужно ОДНО из (иначе HTTP 400):

  cast_voice              id или имя: loki | tom_hardy | thor | Локи | Том Харди | Тор
  cast_mode=speakers      раздать 3 cast-голоса по спикерам по кругу
  voice_sample_male       файл .mp3/.wav (до 10 МБ)
  voice_sample_female     файл .mp3/.wav (до 10 МБ)
  voice_clone_samples     JSON-массив сэмплов (см. ниже)

cast_voice и cast_mode взаимоисключающие.

Дополнительно к сэмплу:

  voice_sample_male_ages / voice_sample_female_ages
      child,teenager,mature,elderly  (пусто = все 4 группы)
  voice_sample_male_ref_text / voice_sample_female_ref_text
      дословный текст сэмпла (рекомендуется)

voice_clone_samples (JSON или form-поле со строкой JSON):

  [
    {
      "gender": "male",
      "sample_path": "/opt/speechlab/server/uploads/voice_samples/demo_male.wav",
      "age_groups": ["mature", "elderly"],
      "ref_text": "Hello, this is my reference voice sample."
    }
  ]

В multipart можно сочетать JSON-метаданные с файлами voice_sample_male/female.

Рекомендации к сэмплу: 10–30 с чистой речи, один спикер, без музыки.


--- 5.3. Режим дубляжа и микс ---

  dub_mode   (алиасы: mode, dubbing_mode)

    voiceover  (по умолчанию)
      Закадровый дубляж. Финальное аудио = full_dub + оригинальная дорожка видео.
      Lipsync не выполняется.

    full
      Без подмеса оригинальной voice/audio дорожки видео.
      Аудио = озвучка + фон demucs (music/noise).
      Sync Labs lipsync по каждой реплике second_seg (speech_*), затем сборка видео.
      На сервере должен быть настроен Sync Labs (клиентский ключ не нужен).

  dub_volume_percent     громкость дубляжа, % (по умолчанию 100; для voiceover)
  original_audio_ratio   доля оригинала 0..1 (по умолчанию 0.3; только voiceover;
                         в full игнорируется)


--- 5.4. Override casting (опционально) ---

  voice_gender / gender   male | female  — для всех реплик
  voice_age               число (лет)    — для всех реплик

Если не заданы — пол/возраст определяются по аудио реплик автоматически.


--- 5.5. Эмоции ---

Клиент эмоции не передаёт. LLM вставляет теги Fish S2 в перевод, например:
  [happy] ..., [sad][whispering] ...
Озвучка читает эти теги.


--- 5.6. Примеры запросов ---

Multipart — cast + voiceover (Windows CMD):

  curl.exe -X POST "https://app.vandum.ru/api/v1/dub" ^
    -H "X-API-Key: ВАШ_КЛЮЧ" ^
    -F "project_name=demo" ^
    -F "source_language=en" ^
    -F "target_language=ru" ^
    -F "cast_voice=loki" ^
    -F "dub_mode=voiceover" ^
    -F "original_audio_ratio=0.3" ^
    -F "video=@C:\Users\Имя\Videos\diolog.mp4"

Multipart — full + свой сэмпл (PowerShell):

  curl.exe -X POST "https://app.vandum.ru/api/v1/dub" `
    -H "X-API-Key: ВАШ_КЛЮЧ" `
    -F "project_name=demo" `
    -F "source_language=en" `
    -F "target_language=ru" `
    -F "dub_mode=full" `
    -F "voice_sample_male=@$env:USERPROFILE\voice_m.wav" `
    -F "voice_sample_male_ref_text=Hello, this is my reference voice sample." `
    -F "video=@$env:USERPROFILE\Videos\diolog.mp4"

Multipart — cast_mode=speakers:

  -F "cast_mode=speakers"

JSON — файл уже на сервере:

  curl -X POST "https://app.vandum.ru/api/v1/dub" \
    -H "X-API-Key: ВАШ_КЛЮЧ" \
    -H "Content-Type: application/json" \
    -d '{
      "project_name": "demo",
      "source_language": "en",
      "target_language": "ru",
      "video_path": "/opt/speechlab/server/uploads/demo_diolog.mp4",
      "dub_mode": "full",
      "cast_voice": "thor",
      "voice_gender": "male",
      "voice_age": 35
    }'

Пример ответа 202:

  {
    "id": "af737c8057f1",
    "status": "queued",
    "project_name": "demo",
    "source_language": "en",
    "target_language": "ru",
    "video_path": "/opt/speechlab/server/uploads/demo_diolog.mp4",
    "created_at": "2026-06-13T17:00:22.422162+00:00",
    "started_at": null,
    "finished_at": null,
    "result_path": null,
    "error": null,
    "options": {
      "dub_mode": "full",
      "cast_voice": "thor",
      "voice_gender": "male",
      "voice_age": 35.0
    },
    "pid": 26832
  }

Сохраните id для опроса и скачивания.

6. GET /api/v1/cast-voices
--------------------------------------------------------------------------------

Список встроенных эталонов (нужен X-API-Key).

  curl.exe -H "X-API-Key: ВАШ_КЛЮЧ" ^
    "https://app.vandum.ru/api/v1/cast-voices"

Ответ:

  {
    "voices": [
      {
        "id": "loki",
        "name": "Локи",
        "gender": "male",
        "sample_file": "AlexGav.wav",
        "sample_path": "...",
        "ref_text": "...",
        "available": true
      },
      { "id": "tom_hardy", "name": "Том Харди", ... },
      { "id": "thor", "name": "Тор", ... }
    ]
  }

В POST /dub передавайте cast_voice=<id> или русское имя.


--------------------------------------------------------------------------------
7. GET /api/v1/jobs/<id>
--------------------------------------------------------------------------------

  curl.exe -H "X-API-Key: ВАШ_КЛЮЧ" ^
    "https://app.vandum.ru/api/v1/jobs/af737c8057f1"

status:
  queued   — в очереди
  running  — пайплайн работает
  done     — можно download
  error    — смотрите поле error

Опрос (PowerShell):

  while ($true) {
    curl.exe -s -H "X-API-Key: ВАШ_КЛЮЧ" `
      "https://app.vandum.ru/api/v1/jobs/af737c8057f1"
    Start-Sleep -Seconds 30
  }

Опрос (bash):

  while true; do
    curl -s -H "X-API-Key: ВАШ_КЛЮЧ" \
      "https://app.vandum.ru/api/v1/jobs/af737c8057f1" | jq .status
    sleep 30
  done


--------------------------------------------------------------------------------
8. GET /api/v1/jobs
--------------------------------------------------------------------------------

До 50 последних задач (от новых к старым). Нужен X-API-Key.

  curl.exe -H "X-API-Key: ВАШ_КЛЮЧ" "https://app.vandum.ru/api/v1/jobs"


--------------------------------------------------------------------------------
9. GET /api/v1/jobs/<id>/download
--------------------------------------------------------------------------------

Только при status=done. Иначе HTTP 409.

Windows CMD (--output ПЕРЕД URL):

  curl.exe -H "X-API-Key: ВАШ_КЛЮЧ" ^
    --output "C:\Users\Имя\Downloads\demo_dubbed.mp4" ^
    "https://app.vandum.ru/api/v1/jobs/af737c8057f1/download"

PowerShell:

  curl.exe -H "X-API-Key: ВАШ_КЛЮЧ" `
    -o "$env:USERPROFILE\Downloads\demo_dubbed.mp4" `
    "https://app.vandum.ru/api/v1/jobs/af737c8057f1/download"

Linux/macOS:

  curl -H "X-API-Key: ВАШ_КЛЮЧ" \
    -o ~/Downloads/demo_dubbed.mp4 \
    "https://app.vandum.ru/api/v1/jobs/af737c8057f1/download"


--------------------------------------------------------------------------------
10. Коды HTTP
--------------------------------------------------------------------------------

  200  OK           — GET health/jobs/cast-voices/download
  202  Accepted     — задача создана (POST /dub)
  400  Bad Request  — нет полей, плохой project_name, нет голоса,
                      неверный dub_mode / cast_mode / gender / age_groups
  401  Unauthorized — нет/неверный API key
  403  Forbidden    — video_path / result вне разрешённых каталогов
  404  Not Found    — job не найден
  409  Conflict     — download до status=done
  413  Too Large    — файл больше лимита upload
  500  Server Error — не удалось стартовать воркер
  503  Unavailable  — пайплайн занят ИЛИ API key не настроен на сервере

Пример 503 (занято):

  {
    "error": "Пайплайн уже выполняется",
    "active_job_id": "b5d778b84a21"
  }

Действие: опрашивайте active_job_id или подождите и повторите POST.

11. Пример клиента на Python (requests)
--------------------------------------------------------------------------------

  import time
  import requests

  BASE = "https://app.vandum.ru"
  HEADERS = {"X-API-Key": "ВАШ_КЛЮЧ"}

  form = {
      "project_name": "demo",
      "source_language": "en",
      "target_language": "ru",
      "dub_mode": "full",          # или "voiceover"
      "cast_mode": "speakers",     # или cast_voice="loki"
  }

  with open(r"C:\path\to\diolog.mp4", "rb") as f:
      r = requests.post(
          f"{BASE}/api/v1/dub",
          headers=HEADERS,
          data=form,
          files={"video": ("diolog.mp4", f, "video/mp4")},
          timeout=600,
      )
  r.raise_for_status()
  job_id = r.json()["id"]
  print("job:", job_id)

  while True:
      st = requests.get(f"{BASE}/api/v1/jobs/{job_id}", headers=HEADERS, timeout=60)
      st.raise_for_status()
      data = st.json()
      print("status:", data["status"])
      if data["status"] == "done":
          break
      if data["status"] == "error":
          raise RuntimeError(data.get("error"))
      time.sleep(60)

  out = requests.get(
      f"{BASE}/api/v1/jobs/{job_id}/download",
      headers=HEADERS,
      timeout=600,
      stream=True,
  )
  out.raise_for_status()
  with open("demo_dubbed.mp4", "wb") as f:
      for chunk in out.iter_content(1 << 20):
          f.write(chunk)
  print("saved demo_dubbed.mp4")


--------------------------------------------------------------------------------
12. Поведение продукта (для UI)
--------------------------------------------------------------------------------

  - Дубляж закадровый (voiceover) или full с lipsync по репликам — не «киношный»
    lip-sync без Sync Labs.
  - Голос только через clone: свой сэмпл или cast_* (VoiceDesign нет).
  - Эмоции задаёт LLM тегами [brackets] в тексте перевода.
  - Повторный POST с тем же project_name и тем же видео может ускориться
    (resume на сервере), если не менялись языки/голос/dub_mode.
  - Перед POST можно смотреть GET /health → active_job, чтобы не ловить 503.


--------------------------------------------------------------------------------
13. Чеклист интеграции клиента
--------------------------------------------------------------------------------

  [ ] Хранить API-ключ только на бэкенде клиента / в секретах, не в публичном JS
  [ ] Обязательно передавать голос (cast / sample / clone_samples)
  [ ] Явно задавать dub_mode, если нужен full
  [ ] Обрабатывать 202, 400, 401, 503
  [ ] Poll job до done/error с backoff 30–60 с
  [ ] Download только при done; сохранить как {project_name}_dubbed.mp4
  [ ] Таймаут upload ≥ размера файла / скорости канала (часто 5–10 мин)
